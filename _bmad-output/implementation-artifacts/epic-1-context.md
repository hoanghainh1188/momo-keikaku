# Epic 1 Context: A Tenant, its people, and nothing leaking between them

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Epic 1 stands up the substrate the rest of the product is built on, expressed as one end-to-end capability: a Tenant Admin can create the organisation (Departments, Programs, Projects, PM assignments, Resources and their dated Rate history), invite PMs, and sign in — with an automated proof that no read ever returns another Tenant's data, and an audit record for every action that changes reported numbers or who can see them. It matters because tenant isolation, the audit trail, exact-integer arithmetic and the application layer are not features that can be retrofitted: every later epic writes through them. Treat this as the largest epic in the plan, not a warm-up — it creates five of the eight workspace units, the whole application layer, the auth stack, the worker role, the adapters, the i18n catalogs and the table-class registry, and it rewires every existing page. At planning time only three of the eight units existed, there was no auth at all, and `apps/web` reached the database directly in eight files; the sizing follows from that gap, not from the phrase "stand up the workspace".

## Stories

- Story 1.1: One command brings the whole system up
- Story 1.2: Nothing crosses a Tenant, and the data layer is what proves it
- Story 1.3: The organisation, and the record of who changed it
- Story 1.4: Sign in, and be revoked
- Story 1.5: Roles decide what each person can reach
- Story 1.6: Resources and the dated Rates behind every money figure
- Story 1.7: The Tenant Admin can read the audit log
- Story 1.8: A load fixture worth measuring against
- Story 1.9: Every string is externalised, and the currency is fixed

## Requirements & Constraints

- **Isolation is provable, not asserted.** A shared harness seeds two Tenants and asserts, for *every* read use case, that nothing from the other Tenant comes back. The harness must enumerate use cases mechanically so a new one is covered the day it is written. This harness plus the FORCE-RLS assertion discharge the isolation NFR once, for the whole product.
- **Org shape.** Tenant › Department › Program › Project. There is no Program table today; story 1.3 creates `program` as a `mutable_audited` table. A Project has one owning Department and an optional Program, and a Program may only be assigned if it belongs to the Project's owning Department. Moving a Project between Programs changes only roll-up — never its Baselines, ledger, Mappings, snapshots or audit history.
- **Roles.** Tenant Admin and PM are assignable in this release; Client Viewer and Internal Viewer exist in the enum but are not assignable. Only a Project's PMs or a Tenant Admin may edit that Project's Plan or Mappings. Rates are writable by Tenant Admins only and visible to Tenant Admins and the PMs of Projects using them. Resources may be created by either role.
- **Sign-in scope.** Email + password and Google only. Magic link and Microsoft are a later release; SAML/SCIM are out of scope. Idle timeout is configurable, default 8 hours. Revocation and idle expiry must take effect on the user's very next request. Password reset requires working mail, so mail is in scope for this release (console mailer locally, SES in production; the AWS account and sender domain belong to Epic 8).
- **Authorisation failures are indistinguishable from absence.** Anything outside a caller's permitted set answers `not_found`, never `forbidden`, so existence is not disclosed.
- **Audit.** Every audited action writes its record inside the same transaction as the change, with actor, time, previous value, and an action drawn from a closed enum. A rolled-back change must leave no audit row. A test enumerates the audited use cases and fails if one commits without a record. The Tenant Admin reads and filters this log; no one else can see it.
- **Rates are bitemporal.** An hour is valued at the Rate in force on its date. A retroactive Rate correction rewrites nothing: the ledger is untouched, money is recomputed against pinned Rate history, and an already-published figure still reproduces exactly.
- **Load fixture.** A deterministic, seed-driven generator produces 5 Projects × 500 Work Packages plus their Resources. Three later epics measure their performance budgets against this one fixture; Epic 5 extends it with Tickets.
- **Localisation.** The UI ships in English with every string externalised and an identically-keyed Japanese catalog present, so a missing key is a build-time gap. Layouts must be verified with Japanese strings 30% longer than the English. Currency is JPY and cannot change once any Rate exists. PM-written notes are displayed as written, never machine-translated. Vietnamese UI is out of scope permanently.
- **Security floor.** No tracker credential may reach logs (redaction covers api keys, tokens, passwords, authorization headers). All tracker- and workbook-sourced text renders escaped; raw HTML injection is a lint error.

## Technical Decisions

- **Shape:** modular monolith, hexagonal, pure functional core. `packages/domain` is pure (no I/O, no clock, no dependency but zod); `packages/app` owns use cases, ports, `RequestContext`, authorisation, audit and config; `packages/db` and `packages/adapters` implement ports; `apps/web` and `apps/worker` are inbound adapters that may only call use cases and the i18n catalogs, never repositories or Drizzle, except through two named carve-outs. Import direction is enforced in CI by dependency-cruiser; the clock/env ban is ESLint's, because dependency-cruiser cannot see calls.
- **The two carve-outs are named paths, not patterns.** (1) `packages/db/auth` is the only sanctioned Better Auth ↔ Drizzle binding and the only unit under `apps/` or `packages/` that imports `better-auth` or any `@better-auth/*` package. It exports a factory, `createAuth({ db, secret, baseURL, idleHours, generateId })`, taking everything as an argument so it reads no environment and imports neither `packages/app` nor `packages/adapters`; an `IdentityPort` adapter over the instance; the web-edge functions run on the instance (the allowlisted route handler, the middleware's session refresh, sign-in, sign-out); and one stateless `hashPassword` for the seed. In `apps/web` only the composition root imports it (outside the graph, `scripts/seed.ts` and `tests/` may). Role, membership and revocation changes never go through it. (2) `apps/web/src/server/composition.ts` is `apps/web`'s composition root: the one file in that app allowed to import `packages/db` (by any specifier, `packages/db/auth` included), and the one file in any app allowed to import `packages/adapters` — to wire the outbound adapters (the `Clock`, the UUIDv7 id generator) into the ports `packages/app` declares. It builds the restricted-role handle, hands `packages/db`'s repository functions to those ports, builds the **one Better Auth instance lazily on first use** (importing the file must read no configuration, or `next build` breaks), and resolves the `RequestContext` per request through `resolveRequestContext`, at most once per render. It holds no Tenant and no audit actor of its own — every binding takes its context from the resolver or from a server action that resolved it once. It wires and never queries or reads the clock itself; it exports use-case bindings, the auth bindings (route handler, session refresh, sign-in, sign-out) and request-context resolution only — never a db handle, the auth instance, a repository function, a Drizzle schema, a clock or an id generator — and it never imports the schedule or plan-input repositories. Any other app needing a composition root must be named in the architecture first; `apps/worker` has none yet and gets one, named and reviewed, the day it first needs an adapter (the fixture-mode `Clock` or the pg-boss queue adapter).
- **`apps/web` → `packages/domain`: the presentation entry module only.** The one further allowed edge is `apps/web` → `domain/present/index.ts`: display formatters, the layout-geometry helpers and the presentation types it re-exports. A page imports nothing that computes; any figure needing a domain rule (money, shares, health flags, Mapping rows, the Client View preview) arrives from a use case already computed. `present/index.ts` never re-exports computation (a test pins its export list), and the jsonb codec is not a page's to call. `apps/worker` has no such edge.
- **What the dependency-cruiser gate enforces now.** It cruises `apps/` and `packages/` only, and turns CI red without blocking a merge (branch protection is unavailable on the private free-plan repository, so every CI gate reports rather than blocks). It fails on: any `apps/*` file importing Drizzle (the composition root included); any `apps/web` file other than the composition root importing `packages/db`, `packages/db/auth` included, and any other app importing `packages/db` at all; any file other than `packages/db/auth` importing `better-auth` or `@better-auth/*`; any `apps/*` file other than the composition root importing `packages/adapters`, and `packages/app`, `packages/domain` or `packages/db` importing `packages/adapters` at all (use cases reach the clock and ids only through ports); any `apps/web` file importing any `packages/domain` module other than `present/index.ts`, by any specifier; the two scheduling edges below and the composition root importing the schedule or plan-input repositories (these match no file yet and were proved live with temporary files); and any import it cannot resolve.
- **What the gate does not enforce yet**, each tracked in the deferred-work log. *Live violation:* `apps/worker` imports `pg-boss` and `pg` directly. *Tolerated, not an import rule:* a few pages still do plain `bigint` arithmetic and date comparisons of their own without importing the domain; nothing gates it. *Unenforced by scope choice:* `apps/web` importing raw `pg`, `apps/worker` importing `packages/domain`, `packages/db` and `packages/app` importing each other (so `packages/db/auth`'s promise not to import `packages/app` is unguarded), `packages/domain` importing anything but zod (its edge to `packages/adapters` is gated), every other diagram edge, and nothing outside `tests/` importing from it. *Not an import rule at all:* the composition root exporting use-case bindings only, never reading the clock, and never re-exporting a clock or id generator; nor re-exporting the auth instance; a re-export is an edge of the composition root itself and so invisible to the gate — a test pins its wiring and review holds the rest. That no constant Tenant id, demo user id or actor literal remains in `apps/web` is a text scan in that test, not an import rule. `scripts/` is operator tooling outside the graph, like `tests/`.
- **Cross-layer tests sit outside the import graph.** The cross-tenant harness lives in a top-level `tests/` area and wires `packages/app` to `packages/db` directly because it must drive both; that is test-only wiring, not a carve-out, and nothing outside `tests/` may import from it.
- **Two scheduling edges are forbidden outright** and should be in the dependency-cruiser config from the start: the schedule domain module may not import attribution, and the schedule and plan-input repositories may be imported only by the app's schedule module — which is also why the composition root may not touch them.
- **Isolation mechanics:** every tenant-owned table carries `tenant_id`, composite foreign keys include it, and each has ENABLE + FORCE row-level security with a policy comparing `tenant_id` to a transaction-scoped session setting. The ORM cannot emit FORCE, so it lives in hand-written SQL with a CI assertion over the catalog that every `tenant_id` table is FORCE'd and has a policy — with one named exception, the tenant-membership bridge, flagged `tenantBridge` in the registry (a registry test fails the flag on any second table). The application role is a non-owner without bypass. All tenant access runs inside `withTenant(...)`, which sets the tenant via a *bound* parameter — the non-parameterizable `SET LOCAL` form is banned outright. A lint rule and a test forbid the bare db handle on tenant-owned tables.
- **Table-class registry:** `packages/db/table-classes.ts` assigns every table exactly one of five classes (append-only, mutable-audited, derived, global, operational), and the RLS, grant and trigger SQL is *generated* from it. CI fails when a migration adds an unregistered table. Identity tables (`auth_user` — Better Auth's `user`, renamed because `user` is reserved — `session`, `account`, `verification`) and `tenant_membership` are `global` (no tenant policy — the session resolves before a Tenant is known). Two per-entry exceptions sit beside the registry entry rather than as new classes: `appPrivileges` gives the application role DML on the four Better Auth tables (Better Auth writes them on that connection) while `tenant` and `tenant_membership` keep SELECT only; and `tenantBridge` as above. The generator and the catalog assertion read grants through one function.
- **One identity bridge:** `tenant_membership(user_id, tenant_id, role, project_ids)` is read only by `resolveRequestContext` in `packages/app/authz`, through the `MembershipReader` port satisfied by `packages/db`'s single reader `membershipsOf`. Its Drizzle table is not re-exported from the `@momo/db` barrel, and a source-discipline test fails if any shipped module other than that reader, the seed and the probe Tenants imports it or names it in a `FROM`/`JOIN`. The session carries an explicit `activeTenantId`, validated against the bridge on every request; Better Auth's session cookie cache is disabled. `IdentityPort` carries only what the resolver needs: read the session without refreshing it, `setActiveTenant` (via Better Auth's internal adapter, since `activeTenantId` is not client-writable), and `endSession` for a session whose Tenant fails validation; a `{ userId, email, locale }` lookup joins it with its first reader (the audit log, 1.7). Sign-in and sign-out are composition-root auth bindings, not port methods. Better Auth tables are reached only through `packages/db/auth`, the owner-role seed and the harness's probe Tenants; that no other module queries them is review-held. `auth_user.locale` is persisted and not client-writable. Role, membership, invitation and revocation changes go through app use cases, never through the auth adapter, so they land in audit.
- **`RequestContext`** is `{ tenantId, userId, roles, projectIds, locale }`, resolved once per render (React `cache()`) and once per server action, which passes it to every binding it calls. The middleware's session read (which slides the session) is a fast path that can only refuse, never a context. Every use case declares its allowed roles and checks project membership; the UI never authorises.
- **Audit mechanism.** Every audited use case calls `audit.record(ctx, action, target, payload)` inside its own `withTenant` transaction; `action` is a closed enum owned by `packages/app/audit`. `audit_log` is itself append-only, and every change to a `mutable_audited` table is mirrored into it. Maintenance-role actions (compaction, tenant purge) run outside any Tenant and write the operator audit table instead (Epic 8). The audited set is the audit NFR's list of action groups; those that land in Epic 1 are role, membership, invitation and revocation changes (1.4, 1.5) and Rate and Project default Rate changes (1.6), plus the organisation changes 1.3 adds (creating, renaming or reassigning Departments, Programs, Projects and PM assignments, each with the previous value). Later epics add their own groups (publish/retract, re-baseline, scheduling inputs, Mappings, dispositions, imports, Connector changes, exports) to the enum and to the enumeration test.
- **Client-facing projection lives outside `present`.** `clientProjection` is a pure function in `domain/client-view`, deliberately not in `domain/present`, so no page can import it; the internal preview renders it through a use case, and R1's Client View reads only the stored client payload.
- **Append-only enforcement is double:** no UPDATE/DELETE grant, plus a BEFORE UPDATE OR DELETE trigger. The only exception path is a `maintenance` role with an explicit maintenance flag.
- **Watermark discipline:** any append to a watermarked table takes `pg_advisory_xact_lock` in its two-argument form (namespace 1 for a Project key, 2 for a Tenant key) *before* allocating a sequence value. Long work happens before the lock.
- **Arithmetic:** effort is `bigint` milli-hours (1 h = 1000) and money is integer JPY. Hours × Rate is `round_half_even(milliHours × yenPerHour / 1000)` per ledger entry, then summed. Ratios are `{num, den}` of bigints, carried unreduced except by an explicit `reduce()`; threshold comparisons use the exact value by cross-multiplication (`spi ≥ 0.95` is `num × 100 ≥ den × 95`) through a single `compareRatio` in the domain's health module, the only comparison site. Fractional spreads are allocated in integer milli-hours by largest remainder with deterministic tie-breaks (date, then resource id). The one float allowed is layout-only: the presentation module's geometry helpers turn a ratio into a float for a bar's width or fill, and that float is never compared, stored, summed or shown as a figure. Rounding happens only in the domain's presentation module (ratios 2 dp, hours 1 dp, yen integer), for both UI and published outputs. Every jsonb read/write of stored values goes through one codec in that module, rendering `bigint` as a decimal string and a ratio as `{num: string, den: string}`, so `JSON.stringify` never meets a bigint. jsonb reorders keys and renormalises numbers, so "identical" always means identical in the codec's canonical decoded form, never column text; a test diffing jsonb text will flake.
- **Clock and config:** wall time comes only from a `Clock` port; `Date.now()`, bare `new Date()` and `process.env` are ESLint errors outside the clock adapter and the config module. Configuration is parsed once by a zod schema that fails boot naming any missing key. **Named exception: Better Auth's own `Date`.** The library stamps session expiry, its tables' timestamps and its refresh decision from its own clock; so session expiry is Better Auth's authority alone, no product code compares a session time against the `Clock` (`resolveRequestContext` never reads one), and no session timestamp is a compute input or an audit time. Identity ids are not exempt: Better Auth gets them from the id port (`generateId`, UUIDv7). Both fences are review-held. A fixture-mode `Clock` does not move session expiry; idle timeouts run on wall time even in the demo. In fixture mode the clock returns the later of the newest fixture timestamp and a configured anchor, and the seed uses the same clock so demos do not go stale.
- **Use-case results:** use cases return a result type carrying a code from a closed enum plus a message key; the domain returns codes, never prose, and server actions map keys through i18n. Zod validates every inbound boundary. IDs are app-generated UUIDv7 (not Postgres's native `uuidv7()`, because ingest needs ids before insert), produced by `packages/adapters/ids` behind `packages/app`'s `IdGenerator` port, with the millisecond taken from the `Clock`. Plan dates are `date`; instants are `timestamptz` in UTC.
- **Local run traps, decided not discovered:** mount the Postgres volume one level above the habitual path (Postgres 18 declares it there and silently ignores the old mount, losing the database on teardown); declare `allowBuilds` because pnpm inherits strict dependency builds; declare `"types": ["node"]` where needed because TypeScript 6 defaults to none; export next-intl middleware from `proxy.ts`; configure Better Auth's Next cookies plugin or session cookies are silently never set. pg-boss's schema is installed and migrated by the owner role during migrate, and the app role starts it with auto-migration disabled holding only DML grants.
- **Leave the doomed columns alone.** Epic 2 owns a single pre-production migration that drops the legacy date columns and creates the status-event table. Epic 1 registers and wraps the 17 existing tables and creates the event tables it needs — and nothing in Epic 1 needs the status-event table.

## UX & Interaction Patterns

- Desktop-first (designed for 1280px+, supported to 1024px). App frame is a 48px top bar (project switcher, snapshot pin, user menu, sidebar toggle) over a collapsible left sidebar and a content area; the admin surfaces this epic builds — Organisation, Resources & Rates, Users, Audit log — are reached from the user menu, not the project sidebar.
- Visual direction is "Ledger Paper, lighter": white sheets on a neutral near-white ground, structure from hairline rules and alignment rather than cards or shadows, one type family (IBM Plex Sans JP), one action colour. Figures are tabular, right-aligned and weighted heavier than body text. No gradients, illustrations, emoji or celebratory motion.
- Microcopy is plain, factual and blame-free; numbers first, then meaning. Dates render `19 Sep 2026` in English and `2026/09/19` in Japanese, always in the Project time zone (default JST), formatted through Intl.
- Accessibility floor is WCAG 2.1 AA: never colour alone, real tables with headers, visible focus rings, navigation landmarks with a skip link, and reduced-motion respected.
- Text sorting goes through a single comparison helper that applies NFKC width normalisation before code-point ordering, so full-width and half-width Japanese forms sort together.

## Cross-Story Dependencies

- The stories are strictly ordered and each builds only on earlier ones. 1.1 (workspace, local run, gates) precedes everything; 1.2 (registry, RLS, `withTenant`, the cross-tenant harness, the rewiring of the eight direct-db files onto use cases — done, with the dependency-cruiser gate switched on only afterwards — and arithmetic and codec discipline) is the foundation for all later data work; 1.3 establishes the audit mechanism that 1.4, 1.5, 1.6 and 1.7 rely on; 1.7 reads what 1.3 writes.
- 1.4 creates the identity tables and request-context resolution that 1.5's role checks depend on; 1.4's password reset depends on the mail port, whose production infrastructure is Epic 8's. 1.7 is the first reader of the identity lookup (`{ userId, email, locale }` for user ids already read under `withTenant`) and adds it to `IdentityPort`.
- 1.6 must create the Project-default-rate table and register it in the table-class registry — it does not exist today.
- 1.8's fixture is the single measurement shape for Epic 2's recalculation budget, Epic 5's snapshot budget and Epic 6's Review load budget; Epic 5 extends the same generator with Tickets rather than building a second one.
- Epic 1 deliberately leaves the legacy Work Package date columns in place; Epic 2's first story removes them in one migration and creates the status-event table. Epic 2 also disposes of the remaining demo-spike files.
